# Recall Ablation Log

本文件记录 OTTO 多路召回的本地开发实验。指标为与比赛一致的加权
Recall@20：

```text
weighted = 0.10 × clicks + 0.30 × carts + 0.60 × orders
```

## 2026-08-03 → 2026-08-10 · Phase 2 全量时间隔离实验

运行范围：全量本地验证集、全量 Top-50 co-vis 邻居表。当前可引用的主结果为
R004；旧的 `0.4911` 使用了会混入验证未来的建表方式，已作废并移到历史记录。

| ID | 候选方案 | Clicks | Carts | Orders | Weighted | Δ Weighted |
|---|---|---:|---:|---:|---:|---:|
| R001 | Recent baseline（最近去重商品） | 0.3065 | 0.2554 | 0.5046 | 0.4100 | — |
| R002 | 加权 self + click co-vis + popularity（时间隔离） | 0.4144 | 0.3047 | 0.5427 | 0.4585 | +0.0485 |
| R003 | 三矩阵 + 分目标路由 + Top-50 + 分块候选 | 0.4530 | 0.3227 | 0.5557 | 0.4755 | +0.0655 |
| R004 | R003 + 确定性 tie-break + 三矩阵全量重建 | **0.4530** | **0.3227** | **0.5557** | **0.4755** | **+0.0655** |

最终三个目标都高于 baseline：clicks `+0.1465`、carts `+0.0673`、orders
`+0.0511`。Weighted Recall@20 提升 `0.0655`（6.55 个百分点），相对
R001 提升约 `16.0%`。加权提升可拆成：

```text
0.10 × 0.1465 + 0.30 × 0.0673 + 0.60 × 0.0511
= 0.01465 + 0.02019 + 0.03066
= 0.06550
```

虽然 clicks 的原始涨幅最大，但 orders 的指标权重是 0.60，因此它对最终提升的
贡献最大。注意 R001→R003 同时包含 self 加权、三张矩阵、Top-50 和热门兜底，
不能把全部增量归因于单一路召回。

### 时间隔离怎么做

- `src/validation.py` 以原始 train 最后 7 天为验证窗口，再把每个验证 session
  随机切成可见的 `val_input` 和隐藏未来 `val_labels`。
- `src/recall/covis.py` 的建表语料是“验证窗口之前的历史 + `val_input`”，不含
  `val_labels` 对应的未来事件。
- `src/recall/popularity.py` 只统计验证窗口边界之前的近期热门，不使用窗口内部事件。
- 本次矩阵用 `python src/recall/run_recall.py --build` 强制重建，避免读取旧缓存。

产物核对：窗口前历史有 `163,955,180` 行，`val_input` 有 `25,888,554` 行，
两者合计 `189,843,734` 行，与 `covis_corpus.parquet` 实际行数完全一致。

### 结果状态

**Current local development CV（当前本地开发分数，已做时间隔离）**：R004 = `0.4755`。

这个结果可以公开写进项目 README 和面试材料，用来说明时间隔离后的真实进展；
但仍不能把 R001→R003 的全部提升直接归因于某张 co-vis 表：

1. R002 同时改变了 self 排序、加入 click co-vis 和 popularity，并非严格的单变量消融。
2. R004 已分目标路由，但 carts 与 orders 当前使用相同矩阵与参数，因此两者预测列表仍完全相同。
3. 这是自建的本地切分，不等同于 Kaggle leaderboard 分数。
4. `VAL_DAYS`/`val_days` 目前在多个文件中分别配置；以后改变验证窗口时必须同步并用
   `--build` 重建语料和矩阵。
5. `run_recall.py --sample` 已不再构建 5/30 矩阵，标准入口只复用或构建全量矩阵；
   但 `build_covis(max_chunks=...)` 仍可被直接调用，且产物没有 manifest，因此 API 层仍缺 provenance 防护。
6. 当前没有自动化测试，也没有保存 Phase 3 所需的候选来源、排名和原始分数长表。

### 已作废的历史结果（仅留审计记录）

| 版本 | Clicks | Carts | Orders | Weighted | 与当前结果的关系 |
|---|---:|---:|---:|---:|---|

旧矩阵曾直接从完整原始 train 建表，而验证答案也来自 train 的最后 7 天，因而隐藏未来
可能进入共现和热门统计。隔离后分数下降是合理现象，不代表模型退步；当前应继续比较的
全量基准是 R003 的 `0.4755`，R002 的 `0.4585` 只作为 Step 1 里程碑。

### 已完成的关键消融与下一阶段

- full 矩阵同口径下，buy-weighted + buy2buy 相比 all-click 约 `+0.0013～0.0014`，属于边际增益。
- Top-N 从 20 提到 50 约 `+0.001`；buy2buy 权重放大到 ×3/×5 反而略降。
- soft blend 为 `0.3107`，明显低于硬分层 `0.3727`，因此已证伪并回退硬分层。

  `0.4777 / 0.5147 / 0.5398`；这是工程回归，不是算法增益。
- 三张矩阵已用新的 `aid_y` 次级排序全量重建；R004 与 R003 四项指标逐位一致，确定性修复完成且没有造成分数漂移。
- 下一阶段保存 Top-100 候选长表与各路特征，进入 GBDT 精排；并完成 Kaggle CV↔LB 对齐。
